Throughput levers · what to change, and by how much

Six settings decide the ML bill. The zero-shot passes come first.

Levers 01, 02, 03, 05 and 06 come from the Claude Code test on Elastic Cloud, 04 from docs/inference-tuning.md. Same models and calls, so they apply to Gemini CLI unchanged.

01 · Allocations

Fixed allocations, provisioned ML minimum

Adaptive allocations did not trigger ML autoscaling. Set number_of_allocations and raise the ML minimum to fit them.

queue 935 → ≤23
02 · Passes

Run fewer zero-shot passes

Cost scales with passes and labels per pass. Security and agent action alone need 2 of the 5 passes.

−60% zero-shot allocations
03 · Scope

Classify by policy, embed everywhere

Inference is a per-policy switch. Classify the teams that need it; everyone else gets embeddings and semantic threat flags.

ML cost ∝ classified share
04 · Threads

One thread per allocation

Ingest-time inference is many small requests. One thread each gave about 2× the work per core of 8-thread allocations.

≈2× per vCPU
05 · Agent output

Small bulk requests

With slow inference, 1,600-event bulks outlived the Cloud proxy timeout and the agent dropped them. bulk_max_size: 200 keeps each request short.

1,600 → 200 events per request
06 · Backfill

Backfill without classification

A new agent reads 30 days of history at once. Turn classification off for the backfill, then back on for live prompts.

6,000 lines in minutes
