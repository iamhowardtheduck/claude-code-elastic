Field notes · deploying to a fresh deployment

Getting to the test found five real issues. All fixed or documented.

These came up installing the integration and a second Elastic Agent on a fresh Elastic Cloud deployment, before any synthetic load ran.

Mappinginput_transformations

Newer Claude Code writes this field as a list of objects. The keyword mapping sent those lines to the failure store.

fixed in 0.2.2: flattened
Agent outputdropped batches

During a classified backfill, 1,600-event bulks hit Cloud proxy 502s and the agent's exporter dropped them, acknowledging the lines. 90 lines were recovered by hand.

bulk_max_size 200, backfill unclassified
Stats inputpipeline prefix

The default prefix matched no pipeline in this package, so no pipeline statistics were collected.

fixed in 0.2.2
Second agentsame host

Elastic Defend blocked an installer run from /tmp, and both agents claimed monitoring port 6791. On Windows a second agent hits an open named-pipe bug (elastic-agent #5306).

install from home, port 6792
AutoscalingML tier

Extra allocations never triggered a memory scale-up, even with a 64 GB maximum.

provision ML minimum up front
